# Голосовой ввод, виджет и тепловая карта — дизайн

Дата: 2026-10-08. Статус: на согласовании.

## Цель и рамки
Три фичи для привлечения пользователей. Ограничения остаются прежними: Android, данные только
на устройстве, без аккаунтов и сервера. Схема базы данных **не меняется**. Каждая фича
выходит отдельным PR в `main` в таком порядке:
1. голосовой ввод и ввод одной фразой;
2. виджет с календарём;
3. тепловая карта загрузки.

## Общее изменение: до 5 точек в клетке
В клетке календаря показывается до **5** точек однодневных событий (раньше было 3).
Лимит общий для приложения и виджета.

## 1. Голосовой ввод и ввод одной фразой

### Поведение
- Точки входа:
  - кнопка микрофона в верхней панели вкладок «Календарь» и «Задачи»;
  - кнопка микрофона в виджете (см. раздел 2).
- Нажатие открывает **окно быстрого добавления** и сразу запускает распознавание речи.
- В окне есть текстовое поле: распознанный текст подставляется туда, фразу можно поправить
  или набрать вручную. Под полем — живой предпросмотр разбора:
  «Созвон с Аней · завтра 15:00 · синий».
- Кнопки окна:
  - **«Сохранить»** создаёт задачу. Неактивна, если название пустое.
  - **«Подробнее»** открывает обычную форму, заполненную разобранными полями.
  - **«Отмена»** закрывает окно.
- Кнопка микрофона внутри окна перезапускает распознавание.

### Распознавание речи
- Используется `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` — системное окно распознавания.
- Параметры: `LANGUAGE_MODEL_FREE_FORM`, язык `ru-RU`, `EXTRA_PREFER_OFFLINE = true`.
- Разрешения RECORD_AUDIO и INTERNET приложению не нужны: звук записывает системное приложение.
- В манифест добавляется `<queries>` для этого intent: это требование видимости пакетов
  на Android 11+.
- Если распознавателя на устройстве нет:
  - кнопки микрофона в приложении скрыты, ввод текстом работает;
  - в виджете кнопка открывает окно быстрого добавления без распознавания.

### Разборщик фразы (`QuickAddParser`)
Чистый Kotlin без зависимостей от Android. Вход — текст и текущий момент `LocalDateTime`.
Выход — `ParsedTask(title, dueAt: LocalDateTime?, endDate: LocalDate?, color: Int?)`.
Регистр не учитывается, «ё» и «е» считаются одной буквой.

| Категория | Поддерживается |
|---|---|
| День | «сегодня», «завтра», «послезавтра»; «в понедельник» … «в воскресенье» (также «в пн» … «в вс»); «12 октября»; «12.10»; «12.10.2026» |
| Время | «в 15», «в 15:30», «в 15.30»; «в 8 утра/дня/вечера/ночи»; «утром» = 09:00, «днём» = 13:00, «вечером» = 19:00 |
| Относительно | «через N минут/часов/дней/недель», «через час», «через неделю» |
| Протяжённость | «с 12 по 20 октября», «с 12 октября по 3 ноября», «на N дней» |
| Цвет | красный, оранжевый, зелёный, бирюзовый, синий, индиго, розовый, фиолетовый (в любой форме слова, например «красным») — соответствуют 8 цветам палитры |
| Числа словами | от одного до десяти (по-разному склоняемые формы) |

Правила:
- **Название** — всё, что осталось после удаления распознанных фрагментов. Лишние пробелы
  и знаки препинания по краям убираются, первая буква делается заглавной.
- Есть дата без времени — ставится 09:00. Для сегодняшнего дня — ближайший круглый час,
  а если он уже завтра, то 23:59. Это существующая функция `defaultDueMillis`.
- Есть время без даты — сегодня, если это время ещё не прошло, иначе завтра.
- Дата без года, которая уже прошла в текущем году, переносится на следующий год.
- День недели означает ближайший такой день, считая сегодняшний.
- «на N дней»: дата окончания = начало + N − 1. Если N ≤ 1, событие однодневное.
- Протяжённость без даты начала начинается сегодня.
- Если в итоге срок оказался в прошлом, срок не ставится. Задача сохраняется без срока.

### Вход из виджета
- Кнопка микрофона в виджете открывает `MainActivity` с action `com.scantfive.planner.action.QUICK_ADD`.
- `MainActivity` обрабатывает этот action в `onCreate` и `onNewIntent`: открывает окно
  быстрого добавления и запускает распознавание.

## 2. Виджет с календарём
- Используется `AppWidgetProvider` и `RemoteViews`. Разметка:
  - заголовок: название месяца и кнопка микрофона;
  - под ним `ImageView` с картинкой месяца.
- Нажатие на картинку открывает приложение, нажатие на микрофон — быстрое добавление.
- **Картинка** рисуется на `android.graphics.Canvas` по той же логике раскладки, что и
  календарь в приложении: `monthWeeks`, `weekSegments`, `dotsFor`, `heatLevel`. Поэтому
  точки (до 5), полосы и тепловая карта выглядят так же. Сегодняшний день выделен кружком.
- Размер картинки подстраивается под размер виджета (`OPTION_APPWIDGET_*`) с ограничением
  на объём памяти. Тема определяется по системной (светлая или тёмная).
- **Обновление:**
  - после каждого сохранения или удаления задачи — через `WidgetUpdater` в `AppContainer`;
  - по `updatePeriodMillis = 30 мин`. Сегодняшний день после полуночи может подсветиться
    с задержкой до получаса.
- Размер можно менять, по умолчанию 4×3 ячейки, минимум 3×2.
- Альтернатива — библиотека Glance — отклонена: в ней сложно сделать полосы через
  несколько дней.

## 3. Тепловая карта загрузки
Фон дня окрашивается основным цветом темы. Насыщенность показывает, насколько близко
**сроки завершения** событий.

- Для каждого невыполненного события важен день завершения:
  - у однодневного события — день срока;
  - у протяжённого — последний день.
- Нагрузка дня D считается с весами:
  `score(D) = 1.0 · ends(D) + 0.5 · ends(D+1) + 0.25 · ends(D+2)`,
  где `ends(X)` — число невыполненных событий, которые завершаются в день X.
- Уровень заливки:

| score | уровень | прозрачность заливки |
|---|---|---|
| 0 | 0 | без заливки |
| (0; 1] | 1 | 0.10 |
| (1; 2] | 2 | 0.20 |
| (2; 3] | 3 | 0.30 |
| > 3 | 4 | 0.40 |

- Выполненные задачи не учитываются. Прошедшие дни подсвечиваются так же — по своим
  событиям в истории.
- Функция `heatLevel(day, events)` — чистая и покрыта юнит-тестами. Её используют и
  приложение, и виджет.
- Не входит: предупреждение о перегрузке по длительности, так как для него нужна новая
  колонка в базе.

## Тестирование
- Юнит-тесты `QuickAddParser`: каждая строка таблицы и правила выше, включая границы —
  прошедшая дата, «на 1 день», пустое название.
- Юнит-тесты `heatLevel`: веса, пороги, выполненные задачи, протяжённые события.
- Сборка и тесты проходят в GitHub Actions.
- Ручная проверка на устройстве — за пользователем: распознавание, виджет, внешний вид.
